RTP Backup

Privacy Notice

Last updated: 3 November 2026

This notice describes the Google Drive integration used by RTP Backup, a privately operated server backup utility configured by the administrator who authorizes access. The tool is used to maintain offsite copies of encrypted backup repositories, not to provide a public file-sharing service.

Information accessed and stored

  • Authorization information: OAuth access and refresh tokens and client configuration needed to connect to the account that the administrator authorizes.
  • Drive metadata: folder and object names, identifiers, sizes, modification times, available hashes, storage quota and connection information needed to locate the backup destination and verify transfers.
  • Backup objects: encrypted repository objects copied from the backup server to the configured Google Drive folder. Backup contents may include business or personal information from the backed-up systems; the uploader transfers the repository objects rather than analyzing their contents.
  • Operational records: transfer status, timestamps, object paths, byte counts and diagnostic errors used to operate and troubleshoot the backup.

Purpose and permission scope

Google API access is used to authenticate the connection, locate the existing backup folder, read relevant metadata or backup objects for verification, and add missing backup objects. The requested Google Drive OAuth scope technically permits broader access than the configured backup folder. The upload job is configured for the administrator-selected destination and does not use unrelated Drive files for another purpose.

The uploader has no advertising, visitor analytics or AI-training feature. Google API data is used for the backup and operational verification described here.

Storage, access and service providers

Authorization credentials are kept in protected configuration files on the administrator's authorized computer and/or backup server. Encrypted backup objects are stored on the backup server and in the chosen Google Drive destination. Operational logs remain with the backup operation. Access to stored copies is governed by server permissions and the Drive account/folder permissions configured by its owner.

The integration necessarily sends backup objects and API requests to Google Drive and uses the operator's configured server hosting. It does not publish backup contents on this information website. Google processes information under its Privacy Policy and applicable service terms.

Retention, removal and revocation

Backup copies are retained according to the administrator's configured backup and retention arrangements. The current Google uploader adds missing objects and does not itself expire or delete existing destination objects. Removal of cloud backups or changes to retention require a separate authorized administrator action.

The account owner can revoke the application's access through Google Account connections. Revocation prevents subsequent authorized transfers; it does not automatically delete copies already stored. For a removal request or an explanation of retention, contact the backup administrator using the User support email displayed for RTP Backup on Google's authorization screen.

These information pages

These static pages contain no credential forms, application scripts or analytics trackers. If hosted on GitHub Pages, GitHub logs visitor IP addresses for security and processes hosting requests under its Privacy Statement. No backup data or OAuth secrets are placed in the public website repository.

Changes and questions

The administrator should update this notice before changing the integration's data use. Any newly required Google permissions must be presented through Google's authorization flow. Questions about access, backup use or removal should be sent to the RTP Backup administrator via the User support email on the Google consent screen.
